# Reversible visual trial decisions

2026-10-23, visual milestone branch. None of these entries changes the design locks.

- Ashen Reliquary is a **PROPOSED** appearance. Muted olive/slate ruins, teal adventurer cloth, oxblood Sentry cloth, ivory Mireling hooks; editable material colours and 2D SVG groups make replacement inexpensive.
- Fixed Blender camera **+75° orthographic** follows L23. Trial azimuth −90° (camera south), target ground origin, orthographic scale 5.4, 192² source canvases. Actor local +Y is north; rotate root −45° per compass step. Lighting never follows root.
- Blender 4.3.2 Workbench studio lighting, material colours, cavity and restrained silhouette outline give a broad-plane miniature test. Physical key/fill references are retained for future EEVEE shading. This is a stylised rig proof, not a final painted character approval.
- Runtime scale: 22.4 trial world units/Blender unit, separate from simulation collision. Source canvas maps to 120.96 world units. Camera zoom is responsive; no collider is inferred from alpha.
- Locomotion four pose samples and guard enter/hold/release three samples at **all eight** facings. Light and Sentry slash/bash initially use N/NE/E/S/SW (SW tests shield-side occlusion). Heavy and low Mireling leap use all eight because asymmetric overhead sword depth and creature launch direction need additional views. Other attack headings remain explicitly unavailable for selective clips pending QA; never use a false quadrant.
- All animation timing and user movement here are **VISUAL-ONLY fixtures**. Preview action phases deliberately use readable exhibition durations. No simulation timing, hits, damage, defense, stamina or enemy decisions exist here.
- Environment masters are modular hand-authored vector-paint SVGs with named editable paint groups, exported by CairoSVG. Broad colour planes and sparse edge brushwork are the reversible first paint pass. They are not a flattened scene background. Further freehand paintover can replace individual groups.
- O1 clear floor remains the proposed 480×440 at world center (950,1750); east/west thresholds are visual routes only. Cover and wall proxy outlines are proposed annotations, **not tested movement/LOS/projectile collision**. There is no gate, sanctuary, loot or fake extraction button.
- Phone portrait uses a local adventurer-focused crop, while desktop and landscape use the full diorama when space permits. Orientation remains open.

2026-10-23, O1 traversal slice (`?scene=o1`). All values below are **trial settings**, kept in `combat/rooms/o1.json`, none is a design lock.

- Source: the deep-stats split in `combat/deep-stats/combat-sim.js`, the source Kyle chose for combat. Baseline for seeded replay: `combat/deep-stats/tools/legacy-golden.json` (78 cells x 20 seeds, legacy arena) and the per-run digest returned by `runO1`, compared between Node and the browser in `tests/browser/o1.spec.ts`.
- Room: 480x440 floor, local frame centre (0,0), x east, y south. North and south walls have inner faces at y = -200 and +200. West and east openings are 174 wide, so a radius-13 body can use the middle 148 units. Pillar at (10,-125), radius 27, the same proxy the study already drew. Wall art is painted on these faces.
- Travel: entry (-240,0), threshold x = 240. Reaching it completes the slice. Grid A* (8 units) around solids inflated by 15, smoothed. The route is fixed, seeds only change the fight.
- Enemy: fixed at the doc-29 test spawn (Mireling (65,80) facing NW, Sentry (90,-25) facing SW). Detection: 160 units, 120 degree cone, blocked by solids. With these spawns the adventurer is always seen, about 160 units out, so the no-contact path is tested with alternate spawns only.
- Hand-off: at detection the simulator receives the adventurer's current position and heading and the enemy's spawn. After a win travel resumes from the simulator's position. Death and the 150 s fight limit stop travel (`defeated`, `unresolved`).
- Perception: the adventurer AI still knows where enemies are through the pillar (handicapped-god model). Solids block movement, hits and projectiles, not the AI's knowledge. Revisit if O1 runs show it matters.
- Not claimed: no human review, no device or touch testing, no combat QA sign-off. Evidence images are software-rendered cloud captures in `docs/o1_slice/`.

2026-10-23, O1 combat detail. The O1 page now shows the simulator's full readout (bars, mind, totals, damage causes, build, log) and in-world cues. The data crosses an additive optional `combat`/`build` field on `PresentationSnapshot`; rendering never reads the simulator directly and never computes damage, arcs or timing. Cues are programmatic placeholders and can be switched off. The enemy guard half-arc (1.3 rad) mirrors the literal in `checkHit`; if the simulator changes it, `o1Combat.ts` must follow.

2026-10-23, O1 multiple enemies. The slice offers four encounters from the simulator: Mireling, Sentry, Two Mirelings, Sentry and Mireling (positions in `combat/rooms/o1.json`, all trial). Each enemy checks sight on its own (160 units, 120 degrees, blocked by solids). When one sees the adventurer, living allies within an alert radius of it (120 units, trial) join that fight; the simulator receives exactly that group. Enemies outside the radius stay where they are and can start a later fight after a win, with the adventurer's remaining health carried over and stamina and poise reset (the simulator has no other carry-over). Fights still run to victory, death or the 150 s limit before travel resumes. The pair spawns sit 78 and 108 units apart, so with the documented layouts the second enemy always joins the first fight; the later-fight path is covered by tests with a distant ally. Enemies never walk into a fight from outside the simulator.

2026-10-23, M0 world foundations. All values are trial settings.
- Rooms and links are generated by `npm run world:build` from `vertical_slice_room_schedule.csv` and `vertical_slice_connections.csv` into `combat/rooms/<id>.json` and `world.json`. `npm run world:check` fails when the committed files differ. Hand-authored data lives in `combat/rooms/overrides/<id>.json`; only O1 has one.
- Geometry rules: floor is the schedule's clear size; wall inner faces sit 20 inside the floor edge on north and south and on the floor edge on west and east; walls are 60 thick; each link becomes a 174-wide door on the wall facing the neighbour along the larger axis (a tie goes to north or south); several doors on one wall are spaced evenly and must leave at least 26 units of wall between them and 20 at the ends. A door is named `to-<room>`.
- Generated rooms are marked `generated`: valid walls, doors and routes for a radius-13 body, with no cover, spawns or encounters, and not art-reviewed. O1 is `authored`.
- `RoomRunner` runs any room from an entry door to an exit door; `O1Controller` is a wrapper, and 72 golden runs (`tests/golden/o1-runs.json`) prove O1's results and digests did not change.
- The save is one versioned JSON text with a checksum, validated before use and before writing, held in browser storage with an in-memory fallback, with export and import for backup. It has no UI yet. It carries placeholders for map memory, banked goods, one cache slot and settings; doc 08's banking rules are checked by `validateInvariants`.
- CI (`.github/workflows/ci.yml`) runs lint, typecheck, world check, unit tests, `regress.js`, `legacy-check.js` and the build on every pull request, and the browser specs in a second job. Not yet observed running on GitHub.

2026-10-23, M1 multi-room traversal. All values are trial settings.
- `WorldRunner` (`src/world/worldRunner.ts`) walks the graph's shortest ordinary path from one room to a turn-around room and back to the start room's centre. Each room is a `RoomRunner`. Between rooms the adventurer walks the straight passage from one door to its paired door at walking speed, in world coordinates (room local position plus the schedule centre), so there is no teleport. Tested: walking steps never exceed walking speed, on every seed.
- The turn-around marks the frontier of the known world: the turn room's first door that is not the way in (O3 to Sunken Passage, `to-S1`). Nothing beyond it is entered.
- Carry-over: health carries between rooms (the simulator still carries nothing else); enemies killed stay dead for the whole walk; living enemies that never fought keep their places and can see the adventurer on any pass. Fights stay inside their room, so enemies are bound to their territory by construction. Nothing in the simulator changed, so doc 07's pursuit and quick alert reset are still not built.
- O2 (Crossroads) and O3 (Broken Causeway) are now authored (`combat/rooms/overrides/`): one pillar each, encounters from the schedule's candidates (O2: Mireling or Sentry; O3: Sentry or Two Mirelings). Camp stays generated and empty. Positions are trial.
- Camp is a safe room only because it has no enemies. It does not heal; banking, rest and supplies belong to M3 and M5.
- Result with the defaults at level 80 balanced and the real 90 health: 17 of the 24 golden walks end in a fall and 7 end back at camp (fights come back to back with no rest). This is the honest cost of health carry-over with no recovery; the level table (M5) and supplies (M3) are what change it. No tuning was done to hide it.
- Golden guard: `tests/golden/world-runs.json` (24 runs) via `npx tsx tools/world-golden.ts --record`. Browser and Node agree on the walk (spec in `tests/browser/o1.spec.ts`, hook `window.__WORLD_RUN__`).
- Not built: a scene that shows the walk (the O1 page still shows one room). That is M2's expedition view. No human, device or combat QA claimed.

2026-10-23, M2 expedition layer. All values are trial settings.
- A plan is up to 5 objectives (Reach or Survey a room), an avoid list, an exploration style (Safe, Thorough, Direct), a doctrine, a health threshold for heading home and a way-home preference. Return to Camp is always appended. Gather, recover, open and challenge objectives wait for the systems they need.
- `WorldRunner` now asks a `Navigator` for the exit door on every arrival. M1's fixed walk is `WalkNavigator` (same ticks, digests and positions; the golden gained two fields, `entry` and `haltReason`). The expedition layer (`src/expedition/`) is a navigator: it picks routes and doors, never tactics, and every choice goes to the intent feed with a cause.
- Map memory: a room is known once entered; a frontier room is an unexplored neighbour by an ordinary link. Routes only cross known rooms and may end at a frontier room; closed gates are walls; avoided rooms are walls for outbound travel, detours and the way home (L13). With no permitted way home the walk stops with `Extraction blocked by your exclusion`; it never crosses the avoided room.
- Route cost: walking distance between room centres; Safe and Thorough add 150 units per danger point of each room entered (labels from the schedule: SAFE 0, EARLY 1, TRIAL and MID 3, HIGH 6, MINIBOSS 8, BOSS and SECRET 10 and 6). It is a label, not odds, and never reads enemy positions. The runner-up route is logged with every choice.
- Finding: in the real graph Safe and Direct pick the same route today. The only loop (Watchtower or Sunken Passage to the Ossuary) has its shorter side also the quieter one (north: 4302 units, danger 20; south: 4524, danger 24). The planner does separate them when a short way crosses a dangerous room (tested on a synthetic diamond). Real route divergence needs shortcuts (M4).
- Thorough differs from Direct on a Survey: it also looks into the target's unvisited neighbouring rooms, one hop, and comes back. That is the bounded survey rule.
- Orders: Retreat and Redirect are queued and take effect at the next doorway, the next legal decision point. A retreat does not interrupt a fight; that needs the disengage work in M3. Observed cost: on a retreat at a doorway the adventurer often walks into the next room's sight line and is caught; in the 6-seed check of a 95% threshold, 4 of 6 died in the room where the threshold tripped (the rest got home).
- L14: an objective with no permitted route is marked Skipped, blocked with the reason and the plan continues in order. Survival retreat is checked at doorways only.
- Screen: `?scene=expedition`, DOM and one canvas, no Phaser. Planner (presets, objectives, standing orders, avoid, preflight with Known route, Ends at unexplored ground, Blocked or Conflicted) and expedition view (schematic map at 0.6 room size, speed 1x 4x 16x, pause, skip, retreat, redirect, objectives, intent feed, Chronicle with JSON download). Ticks drive it, so speed never changes the outcome. There is no per-room tactical view yet; fights show as feed lines.
- Chronicle v1 (`src/expedition/chronicle.ts`) is plain data with no clock: outcome, summary, plan, objective statuses, route, newly mapped rooms, fights and the full intent feed. It is not yet written into the save (M3 does that with banking).
- Not claimed: no human, device or combat QA; phone layout checked only in software captures at 390x844 and 844x390. Nothing is carried, banked or lost yet.

2026-10-23, M3a fighting retreat. All values are trial settings. Loot, banking and the death cache are M3b.
- Simulator, additive and optional (nothing changes without them): `createFight` takes `carry` (stamina and poise); `SIM.order(S, { type: 'disengage', path })` makes the adventurer stop all optional aggression (no new attacks, no light-attack chains) and walk the supplied path while the existing defence still answers every attack; `SIM.retreatReport` returns facts (pursuers, nearest distance, how many in reach, stamina, health, whether it outpaces them); `SIM.leave` ends a fight with winner `escaped`; `SIM.rest` gives stamina and poise recovered over walking ticks. `regress.js` and `legacy-check.js` print `different 0`; O1 golden and the O1 report are unchanged.
- The navigator supplies the path (doc 05); the combat layer executes the disengage. An attack already in flight finishes first, so a retreat can still land the blow that kills.
- `RoomRunner.retreat(door)`: in a fight it plans a route to the chosen door and orders the disengage; while walking it just re-plans. The leg ends the moment the adventurer crosses that door: fight ends `escaped`, survivors go back to their posts (not engaged, positions reset), the dead stay dead. A revisit is a fresh contact.
- Enemies stay in their room (decision recorded with Kyle). Doc 07's chase through connected rooms, last-known-position search and territory-edge behaviour are not built.
- The expedition layer turns a manual Retreat order or the health threshold into a retreat at once, mid-room or mid-fight, no longer only at doorways. Intent feed phases: `Disengage` (with the retreat report), `Withdraw`, `Way home`, then arrival. With no permitted way home it logs `RETREAT BLOCKED`, does not cross the avoided room and the fight carries on (L13).
- Stamina and poise now carry between fights and recover while walking at the simulator's idle rates. The 24 world goldens did not change; the 12 expedition goldens were re-recorded because the 95% plan now retreats mid-fight.
- Finding, stated plainly: a retreat is almost free. At 300 seeds, level 80 balanced, 90 health (`docs/o1_slice/RETREAT_REPORT.md`): with no retreat setting 49% (Guarded), 20% (Measured) and 8% (Pressing) of the Old Road expeditions end back at camp; with a 50% threshold 99.7%, 100% and 99.7% do, losing 2 to 3 health points on the way out and taking 5 to 6 seconds. The cause: enemies are tuned for duelling (circle, approach, attack on a cooldown) and have no chase intent, the door is usually close, and they stop at the room edge by the territory choice. The cost shows up as unfinished plans (all objectives done falls from 49% to 1% at 50%), not as deaths. Nothing was tuned or hidden to change this; no hidden multiplier was added. Whether retreat should cost more is a design call for the loss rules in M3b (banking and the one death cache) and for real pursuit.
- Not claimed: no human, device or combat QA.

2026-10-23, M3b loot, banking, the death cache and the save. All amounts are trial settings. The simulator is untouched.
- Carried loot is a bank-shaped bundle (gold, supplies, found gear, recoverable mastery) held in `Ledger` while the expedition runs. It is at risk until camp. The starter sword and shield are never loot and the save refuses them in a bank or cache.
- Sources, each paid once per enemy or pickup per expedition: kills (Mireling 6 gold and 2 mastery, Ashen Sentry 15 gold and 5 mastery) and authored pickups taken when the adventurer passes within 45 units (a ration in Crossroads, a cracked buckler in Broken Causeway; `pickups` in the room overrides). A full Old Road walk carries 33 gold, 11 mastery, 1 ration and the buckler. The cache joins what is carried when picked up. Disengaging does not pay a kill twice, and the dead stay dead.
- `settle(save, chronicle, startedAt)` is the only place an outcome becomes a save. Extracted: carried loot joins the bank once; a picked-up cache is gone. Died: nothing is banked; what was carried (including a cache picked up on this run) becomes the one cache where the adventurer fell, replacing any waiting cache, whose contents are then lost for good. Map memory, defeated bosses and the counters change whatever the outcome. `startedAt` must equal the save's expedition count, so one expedition cannot be settled twice.
- Decisions the design left open: dying with nothing carried places no cache and leaves an existing cache alone (no ghost marker; doc 08 says to avoid one). An expedition that ends blocked or stopped is not settled: nothing is banked and nothing is lost, because the run is still live; no mid-run save exists yet, so that state cannot be resumed (a gap, stated plainly). Retreat banks nothing; only arriving at camp does.
- Recover is a new objective kind: it walks to the cache position inside its room, picks it up, and carries on. It is valid only when a cache exists there. The cache position is where the adventurer fell, on open floor by construction.
- Save invariants added: no starter kit in a bank or cache, no empty cache, no more deaths than expeditions. The camp screen shows the bank, the cache and a warning that a new fall replaces it; the launch card states what is at risk; the run view shows what is carried; the end report says what was banked, cached or lost, in lines that match the new save. Export and import validate before writing.
- Chronicle is now version 2 (adds the loot block and bosses defeated). Goldens were re-recorded; the earlier fields are identical (checked field by field against the old files).
- Not built: a mid-run save, sanctuaries, supplies that heal (rations are carried and counted but do nothing yet), a Gate Key trial, equipment that changes combat, and a per-room tactical view. The planner screen's map presets are a testing shortcut; the real map memory is the save's discovered rooms.
- Not claimed: no human, device or combat QA.
